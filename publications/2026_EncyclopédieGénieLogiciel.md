# Engineering Patterns
## De l'expérience terrain vers une base de connaissances vivante

> *Document de réflexion - Version 0.1*

---

# Vision

Construire une base de connaissances ouverte consacrée au génie logiciel scientifique, aux systèmes industriels complexes et à l'intégration de l'intelligence artificielle.

L'objectif n'est pas d'écrire un livre figé mais une œuvre évolutive, consultable en ligne, permettant à chacun de retrouver rapidement une problématique d'architecture et les solutions associées.

Cette base deviendra progressivement :

- un ouvrage de référence ;
- une documentation technique ;
- un support de formation ;
- une source pour des conférences ;
- une base documentaire exploitable par une IA ;
- éventuellement le socle d'une future thèse.

---

# Pourquoi ce projet ?

Au cours de plus de vingt années d'expérience dans le développement logiciel scientifique, de nombreuses problématiques reviennent systématiquement :

- Architecture logicielle
- SCADA
- Développement Java
- EPICS
- TANGO
- Support opérationnel
- DevOps
- Intégration Continue
- Qualité logicielle
- Documentation
- Transmission des connaissances
- Formation
- Facteur humain
- Intelligence Artificielle

Ces sujets sont souvent documentés séparément.

L'objectif est de montrer qu'ils appartiennent à une même discipline :

> **Concevoir des systèmes logiciels complexes, maintenables et durables.**

---

# Philosophie

Ce projet ne cherche pas à expliquer un langage.

Il cherche à répondre à une question simple :

> **Quels sont les problèmes récurrents rencontrés dans les systèmes logiciels scientifiques et quelles architectures permettent de les résoudre ?**

Comme les Design Patterns de Gamma ont catalogué les problèmes de programmation orientée objet, cet ouvrage cherchera à cataloguer les problèmes récurrents rencontrés dans l'ingénierie logicielle scientifique.

# Format de publication

Le contenu sera publié progressivement sur GitHub Pages.

Chaque page devra être indépendante.

Le lecteur doit pouvoir arriver directement sur un sujet via un moteur de recherche.

L'organisation sera proche de celle de W3Schools :

- navigation simple
- recherche par thème
- chapitres courts
- liens vers les sujets connexes

# Les "Engineering Patterns"

Le cœur de l'ouvrage sera constitué d'une collection de patterns.

Exemples :

- Expert unique
- Dette technique
- Migration progressive
- Support distribué
- Architecture client / serveur
- Service Layer
- MVC
- Event Bus
- Mode déconnecté
- Historisation
- Alarmes
- Haute disponibilité
- Packaging
- Documentation vivante
- Intégration Continue
- Refactoring progressif
- Architecture modulaire
- Base de connaissances
- Observabilité
- Gestion des incidents
- Transmission des connaissances

---

# Cas d'étude

Chaque pattern sera illustré par un ou plusieurs cas réels.

Par exemple :

- MUSCADE
- EPICS
- TANGO
- SOLEIL
- CERN
- ISEULT
- DESI
- LIQUE4008

L'objectif n'est pas de raconter les projets mais d'expliquer les décisions d'architecture.

---

# Place de l'Intelligence Artificielle

L'IA n'est pas le sujet principal.

Elle est considérée comme un nouvel outil d'ingénierie.

Quelques thèmes :

- Assistant développeur
- Assistant support
- Génération documentaire
- Génération de tests
- Recherche dans la documentation
- Diagnostic assisté
- Agents logiciels
- Copilot scientifique

---

# Place des neurosciences

Le sujet ne porte pas sur les neurosciences fondamentales.

L'objectif est d'étudier la manière dont les humains comprennent des systèmes complexes.

Quelques thèmes :

- Charge cognitive
- Apprentissage
- Représentation mentale
- Documentation
- Visualisation
- UX
- Mémoire externe
- Collaboration Homme / IA

# Méthode de travail

Le projet sera développé de manière incrémentale.

Aucun objectif de complétude immédiate.

Chaque nouvelle idée pourra devenir :

- une note
- un brouillon
- un chapitre
- un pattern
- une vidéo
- une conférence

L'objectif est de construire progressivement une œuvre vivante.

---

# Principe fondamental

> Ne jamais écrire un contenu pour un seul usage.

Chaque contenu doit pouvoir être réutilisé sous plusieurs formes :

```
Idée
    ↓
Note
    ↓
Pattern
    ↓
Chapitre
    ↓
Article
    ↓
Vidéo
    ↓
Conférence
    ↓
Formation
    ↓
Publication
```

# Ambition

Construire, au fil des années, une référence francophone (et à terme anglophone) sur l'ingénierie des systèmes logiciels scientifiques.

Une ressource libre, durable et évolutive, permettant de transmettre une expérience acquise sur le terrain aux générations suivantes.

> "L'expérience n'a de valeur que lorsqu'elle devient transmissible."
